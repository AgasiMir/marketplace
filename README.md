Современное REST API для онлайн-маркетплейса на базе FastAPI с полным набором функций для управления товарами, пользователями, заказами, корзиной, избранным и отзывами.

## 🚀 Основные возможности

- **Аутентификация и авторизация** (JWT, роли покупатель/продавец)
- **Управление товарами** с фильтрацией, сортировкой, полнотекстовым поиском
- **Категории товаров** с древовидной структурой
- **Корзина покупок** для авторизованных пользователей
- **Избранное** с ограничением количества товаров
- **Отзывы и рейтинги** к товарам
- **Оформление заказов** с различными статусами
- **Административная панель** (SQLAdmin) для управления данными
- **Кэширование** с Redis для повышения производительности
- **Очереди задач** через Celery + RabbitMQ для асинхронной обработки
- **Email-уведомления** через SMTP (MailDev для разработки)
- **Мониторинг и метрики** (Prometheus, Grafana)
- **Логирование** структурированных запросов
- **Лимитирование запросов** (rate limiting)
- **Полнотекстовый поиск** с использованием PostgreSQL TSVECTOR
- **Тесты** с покрытием >90%

## 🏗️ Архитектура

Проект построен по принципам чистой архитектуры с разделением на слои:

- **Доменный слой** (`app/domains/`) — бизнес-логика, схемы, репозитории, сервисы, роутеры
- **Слой данных** (`app/models/`) — модели SQLAlchemy
- **Слой инфраструктуры** (`app/connectors/`, `app/email/`, `app/tasks/`) — внешние сервисы
- **Слой утилит** (`app/utils/`, `app/middlewares/`) — промежуточное ПО, метрики

## 🚀 Быстрый старт

### Предварительные требования

- Docker и Docker Compose
- Python 3.12+ (для локальной разработки)
- Git

### Запуск через Docker Compose

1. Клонируйте репозиторий:
```bash
git clone <repository-url>
cd marketplace
```

2. Создайте файл окружения (на основе примера):
```bash
cp .env.example .env.prod
# Отредактируйте .env.prod при необходимости
```

3. Убедитесь, что в классе `Settings` (файл `app/config.py`) установлена настройка `model_config = SettingsConfigDict(env_file=[".env.prod"])`. По умолчанию она уже настроена, но проверьте, что файл `.env.prod` указан корректно.

4. Запустите все сервисы:
```bash
docker-compose up --build -d
```

5. Приложение будет доступно по адресам:
   - **API**: http://localhost:8000
   - **Документация Swagger**: http://localhost:8000/docs
   - **Документация ReDoc**: http://localhost:8000/redoc
   - **Админ-панель**: http://localhost:8000/admin
   - **Grafana**: http://localhost:3000
   - **Prometheus**: http://localhost:9090
   - **Flower (Celery)**: http://localhost:5555
   - **RedisInsight**: http://localhost:5540
   - **MailDev**: http://localhost:1080
   - **RabbitMQ Management**: http://localhost:15672 (guest/guest)

### Локальная разработка

1. Установите зависимости через uv:
```bash
uv sync
```

2. Создайте файл окружения (на основе примера):
```bash
cp .env.example .env.dev
# Отредактируйте .env.dev при необходимости
```

3. Убедитесь, что в классе `Settings` (файл `app/config.py`) установлена настройка `model_config = SettingsConfigDict(env_file=[".env.dev"])`. 

4. Запустите сервисы зависимостей через Docker:
```bash
docker-compose up -d postgres redis rabbitmq maildev
```

5. Примените миграции:
```bash
alembic upgrade head
```

6. Запустите сервер разработки:
```bash
uvicorn app.main:app --reload
```

7. Запустите Celery worker (не обязательно):
```bash
celery -A app.tasks.celery_app:celery_instance worker --loglevel=info (-P gevent в случае с Windows)
```

### Роли пользователей

- **buyer** (покупатель) — может просматривать товары, добавлять в корзину, создавать заказы, оставлять отзывы
- **seller** (продавец) — все возможности покупателя + создание/редактирование своих товаров
- **admin** (администратор) — полный доступ ко всем ресурсам через админ-панель, а также к эндпойнтам

## 🗄️ База данных

### Основные модели

- **User** — пользователи с ролями и аутентификацией
- **Product** — товары с ценами, описанием, категориями
- **Category** — категории товаров (иерархическая структура)
- **CartItem** — товары в корзине пользователя

### Миграции

Проект использует Alembic для управления миграциями:

```bash
# Создать новую миграцию
alembic revision --autogenerate -m "Описание изменений"

# Применить миграции
alembic upgrade head

# Откатить миграцию
alembic downgrade -1
```

## ⚡ Производительность

- **Redis** используется для кэширования часто запрашиваемых данных

- Ключи кэша строятся на основе параметров запроса и пользователя

- **Полнотекстовый поиск** через PostgreSQL TSVECTOR

## 📊 Мониторинг и логирование

### Метрики Prometheus

Приложение предоставляет метрики по адресу `/metrics` (экспортируются через `prometheus-client`):

- `http_requests_total` — общее количество HTTP-запросов (Counter) с лейблами `method`, `endpoint`, `status_code`
- `http_request_duration_seconds` — время выполнения HTTP-запросов (Histogram) с лейблами `method`, `endpoint`, `status_code` и бакетами [0.1, 0.3, 0.5, 1.0, 2.0, 5.0] секунд
- `active_connections` — текущее количество активных соединений (Gauge) с лейблом `app`
- `active_requests` — количество активных HTTP-запросов в данный момент (Gauge) с лейблами `method`, `endpoint`

Метрики собираются автоматически через middleware `metrics_middleware.py` и обновляются в реальном времени.

### Настройки Grafana

   - Перейти по `http://localhost:3000` (если запущен)
   - В меню Data sources выбрать Prometheus 
   - Указать `http://prometheus:9090` в Prometheus server URL
   - Нажать Save&Test
   - В меню Dashboards выбрать Import 
   - Вставить содержимое файла grafana_dashboad.json и нажать Load, а затем Import

### Логирование

- Структурированные логи в формате JSON
- Уровни логирования: DEBUG, INFO, WARNING, ERROR
- Логирование входящих запросов с временем выполнения
- Интеграция с Loguru
